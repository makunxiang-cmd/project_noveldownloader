# NDL v0.2 Release Notes

NDL (NOVELDOWNLOADER) v0.2 is the first feature release after v0.1. The
focus is **closing the gap between upstream and downstream consumers** —
every change in this release was driven by a workaround that the
`ndl-desktop` GUI had to ship because the upstream YAML rule schema or
service layer couldn't express the behavior. See
`docs/agents/downstream-feedback/2026-05-23-ndl-desktop.md` for the full
ledger.

> Distribution name: `ndl-storykit`. After the 0.2 ship, install with
> `pip install ndl-storykit==0.2.*` (and `pip install 'ndl-storykit[browser]==0.2.*'`
> for the Playwright fetcher).

## Highlights

- **Browser fetcher lifecycle is correct.** `_PlaywrightBrowserSession.aclose()`
  now stops the started Playwright instance (not the context manager). Browser
  startup-failure paths cleanly release the partially-started runtime instead
  of swallowing the error and leaking a headless Chromium process.
- **Paginated indexes and split chapters.** `DownloadService` now consumes
  `rule.index.pagination`: `type: next` follows `pagination.next` selectors
  with URL de-duplication and a cycle guard; `type: index-template` iterates a
  URL template until the page yields no new stubs or `max_pages` is hit.
  `DownloadService` also consumes `rule.chapter.pagination.type: next` to
  merge same-chapter pages into one `Chapter` body, using stem-matching to
  avoid following the "next" link into the next chapter.
- **Whole-book TXT archive downloads.** New `download_archive` rule block
  describes a TXT (or selector-triggered) archive endpoint. `DownloadService`
  fetches the archive bytes, decodes against a configurable encoding list,
  strips site-injected noise lines, and splits against the index chapter
  titles.
- **POST and browser-form search.** `search.method: POST` with form `body`
  values is now expressible in YAML. For browser-rendered search forms,
  `search.browser` describes navigate URL, input selector, submit selector,
  and the wait-for trigger; `SearchService` reuses the browser fetcher's
  session bootstrap. Multi-source results are now de-duplicated by
  `(source_rule_id, url)` before return.
- **Update service shares the download pipeline.** `UpdateService` no longer
  duplicates download logic. It now consults `rule.index.pagination`, diffs
  against stored chapters by URL (more robust than the previous index-based
  diff), and reuses the per-rule fetcher pool that landed in v0.1.
- **TXT import is upsert-friendly.** Files without a `来源:` line now default
  `source_url` to `file://{absolute path}`, so re-importing the same TXT
  upserts instead of duplicating the library row. The reader also recognises
  `书名:`, `标题:`, `Title:` (any case) as title-line prefixes and strips them
  to the bare title.
- **Container disambiguation in selectors.** `chapter_list.container` now
  accepts a `pick:` modifier (`first` / `last` / `largest`) to disambiguate
  when the selector matches multiple containers — e.g., a site with a
  "latest 12 chapters" strip and a full list both rendered as
  `ul.section-list`.
- **Styled EPUB output by default.** The default EPUB writer now emits a
  cover (when `novel.cover_url` or `novel.cover_data` is set), a title page
  with summary metadata, and a styled chapter layout (Songti/Source-Han
  serif, justified body, 2em first-line indent, centred chapter titles with
  page breaks and an ornament divider). Output is rendered consistently
  across Apple Books, KOReader, and Calibre.
- **Schema consumption is documented.** A new "Schema Consumption" table in
  `docs/rule-authoring/README.md` enumerates every schema field with its
  "Schema since" and "Consumed since" version, so a rule author can tell at a
  glance whether a field is wired through or only validated.
- **The demo rule no longer ships in production.** `load_builtin_rules()`
  returns an empty list in the default install; the static-HTML example
  moved to `tests/fixtures/rules/example_static.yaml` for upstream tests
  only.

## Compliance Boundaries

These are intentional product limits, not bugs:

- robots.txt is **respected by default**. A rule may opt out only by
  declaring `robots.respect: false` together with a non-empty
  `ignore_justification`.
- Per-host rate limit defaults to `min_interval_ms: 1000` and
  `max_concurrency: 1`, capped at `≤3` concurrent requests. The throttle is
  shared across all novels under the same rule for one `update --all` run.
- `ndl download` is gated behind a first-run lawful-use disclaimer; the
  acceptance marker lives at `<NDL_HOME>/disclaimer.accepted`.
- **Out of scope, permanently:** commercial novel platforms; login,
  CAPTCHA, paywall, Cloudflare-challenge, or other anti-bot bypasses; proxy
  pools; credential storage.
- Remote rule downloads require `https` by default. The
  `NDL_RULES_ALLOW_INSECURE=1` escape hatch exists for local mirrors and
  testing — not for production fetches.

## Quick Start

After the 0.2 ship completes:

```bash
# Install
pip install 'ndl-storykit==0.2.*'
# Or with the optional browser extra:
pip install 'ndl-storykit[browser]==0.2.*'
playwright install chromium

# Download to a styled EPUB
ndl download https://example-novels.test/book/123 -o book.epub --accept-disclaimer

# Convert a local NDL TXT file
ndl convert book.txt -o book.epub

# Inspect saved novels
ndl library list
ndl library show <id>

# Refresh saved ongoing novels (append-only)
ndl update --all --accept-disclaimer

# Search across rule-enabled sources (now includes POST and browser-form rules)
ndl search "白蛇传"

# List or validate rules
ndl rules list
ndl rules validate path/to/rule.yaml

# Pull remote rules (https only by default)
NDL_RULES_MANIFEST_URL=https://your-mirror/example/manifest.yaml \
  ndl rules update --yes

# Run the local Web UI on 127.0.0.1:8000
ndl serve --accept-disclaimer
```

## Reliability Hardening

- Every browser-source close path correctly stops the started Playwright
  runtime; failure paths release the partially-started runtime instead of
  silently leaking a headless Chromium process.
- `DownloadService` URL-deduplicates across paginated index pages and
  cycle-guards "next" link chains so a misbehaving site cannot drive an
  infinite loop.
- `UpdateService` diffs against stored chapters by URL rather than by index,
  so a site that inserts a chapter mid-list no longer reshuffles every
  stored chapter's identity.
- TXT imports default `source_url` to `file://{absolute path}` so re-imports
  upsert deterministically against the existing library row.

## What's Not Included in v0.2

- **No bundled remote rule feed.** Same as v0.1: rules can be authored
  locally or pulled from a manifest URL you provide; NDL does not ship a
  default catalog.
- **No automatic deletion of remote-installed rules.** The remote-update
  flow installs and replaces; it does not prune locally-installed rules
  that disappear from a manifest.
- **No archive ZIP support.** `download_archive.format` currently accepts
  only `txt`. ZIP archives can be added when a real site demands them.
- **No login, CAPTCHA, paywall, Cloudflare-challenge, or proxy-pool
  behavior.** Out of scope permanently — see Compliance Boundaries.
