# NDL v0.1 Release Notes

NDL (NOVELDOWNLOADER) is a rule-driven Chinese novel downloader and format
converter for static HTML public-domain sources. v0.1 is the first public
release; the focus is **reliable downloads, auditable behavior, and a small
local toolchain** that respects the sites it talks to.

> Distribution name: `ndl-storykit` (the PyPI name `ndl` was already taken
> in 2016 by an unrelated abandoned project). Python import path and CLI
> entry point are both still `ndl`.

## Highlights

- **Rule-driven downloads.** YAML site adapters describe URL patterns, robots
  policy, rate limit, retry, encoding, and the selectors required to parse
  index and chapter pages. `ndl download <url> -o book.epub` resolves the
  matching rule and writes TXT or EPUB.
- **TXT and EPUB output.** `ndl convert` runs the same pipeline against a
  local NDL TXT file. Both formats share one in-memory `Novel`/`Chapter` IR.
- **Local SQLite library.** Downloads optionally persist to
  `<NDL_HOME>/library.db` (default `~/.ndl/`). `ndl library list/show/remove`
  inspects the library; `ndl update --all` and the Web UI re-fetch saved
  ongoing novels and append only the chapters that are new — never
  overwriting stored data.
- **Web UI.** `ndl serve` starts a local FastAPI app on `127.0.0.1:8000` that
  lists the library, runs downloads in background tasks with live Server-Sent
  Events progress, exposes the same search and update flows, and refuses to
  bind a public interface unless `--allow-public-host` is passed.
- **Multi-source search.** `ndl search "<keyword>"` queries every enabled
  rule that declares a `search` block and prints a results table plus a
  separate "Search failures" table for any source that erred. One broken
  source no longer takes down the entire search.
- **Remote rule updates.** `ndl rules update --manifest-url <https://...>`
  fetches every referenced YAML rule **concurrently**, optionally verifies
  per-rule SHA-256, validates the full bundle, and prompts before writing to
  `<NDL_HOME>/rules/`. Non-`https` URLs are rejected by default; set
  `NDL_RULES_ALLOW_INSECURE=1` to allow `http` for local mirrors only.
- **Optional Playwright browser fetcher.** Rules can declare
  `fetcher.type: browser` to render JS-heavy pages. Available via the
  `ndl[browser]` extra and `playwright install chromium`; `ndl doctor
  browser` reports whether both are wired up.
- **Auditable release artifacts.** `scripts/verify_distribution.py` checks
  the freshly built wheel and sdist for the required builtin rule, Web
  templates, static assets, and metadata extras (including `browser`).

## Compliance Boundaries

These are intentional product limits, not bugs:

- robots.txt is **respected by default**. A rule may opt out only by
  declaring `robots.respect: false` together with a non-empty
  `ignore_justification`.
- Per-host rate limit defaults to `min_interval_ms: 1000` and
  `max_concurrency: 1`, capped at `≤3` concurrent requests. The throttle is
  shared across all novels under the same rule for one `update --all` run.
- `ndl download` is gated behind a first-run lawful-use disclaimer; the
  acceptance marker lives at `<NDL_HOME>/disclaimer.accepted`.
- **Out of scope, permanently:** commercial novel platforms; login,
  CAPTCHA, paywall, Cloudflare-challenge, or other anti-bot bypasses; proxy
  pools; credential storage.
- Remote rule downloads require `https` by default. The
  `NDL_RULES_ALLOW_INSECURE=1` escape hatch exists for local mirrors and
  testing — not for production fetches.

## Quick Start

```bash
# Install
pip install ndl-storykit
# Or with the optional browser extra:
pip install 'ndl-storykit[browser]'
playwright install chromium

# Download to EPUB, save into the library
ndl download https://example-novels.test/book/123 -o book.epub --accept-disclaimer

# Convert a local NDL TXT file
ndl convert book.txt -o book.epub

# Inspect saved novels
ndl library list
ndl library show <id>

# Refresh saved ongoing novels (append-only)
ndl update --all --accept-disclaimer

# Search across rule-enabled sources
ndl search "白蛇传"
ndl search "白蛇传" --rule example_static --limit 10

# List or validate rules
ndl rules list
ndl rules validate path/to/rule.yaml

# Pull remote rules (https only by default)
NDL_RULES_MANIFEST_URL=https://your-mirror/example/manifest.yaml \
  ndl rules update --yes

# Run the local Web UI on 127.0.0.1:8000
ndl serve --accept-disclaimer
```

## What's New Since the Empty State

v0.1 is the first user-visible release; every feature below is new.

- **CLI surface:** `download`, `convert`, `library list/show/remove`, `search`,
  `update --all`, `serve`, `rules list/validate/update`, `doctor browser`.
- **Web surface:** library home, library detail, search form + results,
  download form with SSE progress, manual update-all action, recurring
  background updates while the server is running.
- **Storage:** SQLite with WAL + foreign keys, SQLAlchemy 2.0 models,
  append-only chapter merge, lifecycle-managed engine.
- **Scheduler:** APScheduler-backed recurring update job while `ndl serve` is
  active; configurable interval (`--update-interval-hours`).
- **Diagnostics:** `ndl doctor browser` reports Playwright install + Chromium
  runtime status; browser fetch errors include actionable install hints.

## Reliability Hardening (Pre-Release P0/P1/P2)

A separate hardening pass landed alongside the feature work; details in
[`docs/superpowers/plans/2026-05-13-ndl-p7-pre-release-hardening.md`](https://github.com/makunxiang-cmd/project_noveldownloader/blob/main/docs/superpowers/plans/2026-05-13-ndl-p7-pre-release-hardening.md).
The user-visible parts:

- A re-download that returns **fewer** chapters can no longer wipe stored
  data; `save()` is append-only on chapters.
- A failing search source no longer hides successful sources' results.
- The Web job registry has a default 100-job cap and never evicts active
  jobs, so long-running `ndl serve` stops leaking memory.
- `update --all` reuses one fetcher per rule for the entire batch (no
  Playwright cold-start, robots re-fetch, or throttle reset per novel).
- Web SSE streaming is event-driven; progress updates reach the browser as
  soon as they are recorded.
- Browser fetcher startup failures no longer leak partially-started
  Playwright subprocesses.
- Remote rule manifests are fetched **concurrently** and require `https` by
  default.

## What's Not in v0.1

- **No bundled remote rule feed.** Rules can be authored locally or pulled
  from a manifest URL that you provide; NDL does not ship a default catalog.
- **No browser-rendered search.** Search is HTTP-only; `fetcher.type: browser`
  applies to download/update.
- **No automatic deletion of remote-installed rules.** The remote-update flow
  installs and replaces; it does not currently prune locally-installed rules
  that disappear from a manifest.
