## Purpose

Bring the `ndl-storykit` 0.2 development line into a maintainer-ready state.
Every 0.2 track from the downstream feedback doc has been merged except track
G (styled EPUB), which is open as PR #15. This spec covers the agent-driven
work to land G, verify shippability on `main`, and stage release artifacts so
the maintainer's remaining work collapses to: review one doc PR, paste a
small version-bump diff, tag, push, GitHub Release, PyPI upload.

## Non-Goals

Crossing the Execution Gate defined in `docs/developer/release.md`. The agent
must stop before bumping the version, dating the CHANGELOG heading, creating
the release commit/tag, opening the GitHub Release, or uploading to PyPI —
regardless of how the request is phrased.

## Phases

### Phase 1 — Land PR #15

1. Re-run only the failed cells:

   ```bash
   gh run rerun 26338133599 --failed
   ```

2. Wait for the matrix to go green across all 15 cells.
3. Squash-merge to match the repo's prior pattern (every merged 0.2 PR shows
   `(#N)` in its main-branch commit title):

   ```bash
   gh pr merge 15 --squash --delete-branch
   ```

4. Sync the local tree:

   ```bash
   git switch main && git pull
   ```

**Failure handling.** If the rerun still fails on ubuntu cells, treat it as a
real failure — pull the cell log, diagnose, fix on the branch, push, repeat.
Do not merge with `--admin` and do not skip the matrix. If `gh pr merge`
itself fails (branch protection, missing approval), stop and report; the
merge button is the user's call.

### Phase 2 — Preflight on `main`

Run the exact sequence from `docs/developer/release.md` §§ Preflight, Build
Artifacts, Install Smoke. On `main` after the Phase 1 merge:

```bash
uv lock --check
uv run ruff check .
uv run ruff format --check .
uv run mypy src/ndl
uv run pytest --cov=ndl --cov-report=term --cov-report=xml
uv run pre-commit run --all-files

uv build --wheel --sdist --out-dir dist
uv run python scripts/verify_distribution.py \
    dist/ndl_storykit-*.whl dist/ndl_storykit-*.tar.gz

python -m venv /tmp/ndl-smoke
/tmp/ndl-smoke/bin/pip install --upgrade pip
/tmp/ndl-smoke/bin/pip install dist/ndl_storykit-*.whl
/tmp/ndl-smoke/bin/python scripts/smoke_cli.py --ndl /tmp/ndl-smoke/bin/ndl
```

All commands must exit 0. The build artifacts in `dist/` are throwaway
(gitignored) — they prove the wheel and sdist are well-formed for the
maintainer to rebuild from the eventual release tag.

**Failure handling.** If preflight fails on `main` after PR #15 merged, PR
#15 introduced a regression that interacts with another merged track. Report
verbatim, stop, do not draft release notes against a broken main. If
`verify_distribution.py` or `smoke_cli.py` fails, the wheel is missing a
required file (templates / static / metadata extras); investigate and fix
on a new branch rather than editing the verifier's expectations.

### Phase 3 — Release-notes PR (doc-only, agent-safe)

New branch `docs/release-notes-v0.2` with exactly two file changes:

1. **`docs/release-notes/v0.2.md`** — single-page user-facing notes mirroring
   the structure of `docs/release-notes/v0.1.md`:
   - Highlights (sourced from `CHANGELOG.md` `[Unreleased]` Added/Changed/Fixed
     and the merged 0.2 PR titles)
   - Compliance Boundaries (verbatim from v0.1; these don't change)
   - Quick Start (deferred install instructions — leave as "after the 0.2 ship,
     `pip install ndl-storykit==0.2.*`" rather than asserting the package is
     live, because at PR time it isn't yet)
   - Reliability Hardening (track A summary)
   - What's Not Included (commercial sites, login automation, CAPTCHA,
     paywall, Cloudflare, proxy pools — the standard list)
   - Quality Snapshot (test count, coverage from the Phase 2 run)
   - Execution Gate reminder

2. **`docs/mkdocs.yml`** — add a `Release Notes → v0.2` nav entry alongside
   the existing v0.1 entry.

**No other file changes in this PR.** Specifically: no version-string bumps,
no CHANGELOG dated heading, no README "now on PyPI" claims, no installation
pointer flips. Those all belong to the maintainer's release commit.

**Failure handling.** Review feedback on the doc PR is normal; revise and
push. Doc-only PRs cannot ship anything material, so iteration is cheap.

### Phase 4 — Maintainer handoff

The remaining work is the runbook in `docs/developer/release.md` §
Maintainer Runbook, steps 1–11. The agent does not execute any of those
steps. Instead, this spec ends with a paste-ready checklist (below) that
enumerates exactly which strings to change in which files, so the maintainer
can apply the diff with minimal effort.

If the maintainer requests any step past the gate, the agent must quote the
relevant runbook step and stop, per the explicit `docs/developer/release.md`
instruction that this rule applies regardless of how a request is phrased.

## Out of Scope — the Execution Gate

Verbatim from `docs/developer/release.md`:

| Action | Why agent will not do it |
|---|---|
| Bump `0.2.0.dev0` → `0.2.0` in `pyproject.toml` / `src/ndl/__init__.py` / `uv.lock` / verifier expectations | maintainer-only |
| Edit `CHANGELOG.md` to add `## [0.2.0] - YYYY-MM-DD` heading | maintainer-only |
| Create the release commit (`chore(release): NDL v0.2.0`) | maintainer-only |
| `git tag -s v0.2.0` / `git push origin v0.2.0` | maintainer-only |
| `gh release create v0.2.0 ...` | maintainer-only |
| `uv publish` / `twine upload` | maintainer-only |
| Bump to `0.3.0.dev0` post-ship | maintainer-only |

## Verification

Success criteria for the agent-driven phases:

1. **After Phase 1:** `main` HEAD contains the squash-merged G1 commit.
2. **After Phase 2:** `uv run pytest --cov=ndl` passes; `verify_distribution.py`
   and `smoke_cli.py` exit 0; `dist/ndl_storykit-0.2.0.dev0-py3-none-any.whl`
   and `dist/ndl_storykit-0.2.0.dev0.tar.gz` exist.
3. **After Phase 3:** A doc-only PR is open with `docs/release-notes/v0.2.md`
   and the `docs/mkdocs.yml` nav entry, and no version-string or CHANGELOG
   mutations.
4. **After Phase 4:** This spec contains a paste-ready maintainer checklist
   and the agent has stopped at the gate.

No new tests are introduced — every PR up to 0.2 added the regression tests
for its own track.

### CHANGELOG transformation

Current state of `CHANGELOG.md` (top):

```markdown

### Changed
- Post-release housekeeping: ...
- ... (all 0.2 entries) ...

### Added
- Rule pagination is now consumed by `DownloadService`: ...
- ... (all 0.2 entries) ...

- ... (all 0.2 entries) ...

```

Target state of `CHANGELOG.md` (top) — substituting the actual release date:

```markdown
## [Unreleased]

## [0.2.0] - YYYY-MM-DD

### Changed
- Post-release housekeeping: ...
- ... (all 0.2 entries, unmodified) ...

### Added
- Rule pagination is now consumed by `DownloadService`: ...
- ... (all 0.2 entries, unmodified) ...

### Fixed
- Browser-backed fetches now stop the started Playwright runtime ...
- ... (all 0.2 entries, unmodified) ...

## [0.1.0] - 2026-05-13
...
```

The transformation: add an empty `## [Unreleased]` placeholder above, and a
dated `## [0.2.0] - YYYY-MM-DD` heading below it that owns the existing
content. Do not edit the content under it.

### Runbook commands

Steps 1–11 of `docs/developer/release.md § Maintainer Runbook` — reproduced
here for convenience, with concrete commands. The maintainer executes these:

```bash
# 1. Confirm clean tree on a fresh release branch off main.
git switch main && git pull
git switch -c release/v0.2.0

# 2. Apply the version-string edits listed above (manually or via sed),
#    then regenerate the lock:
uv lock

# 3. Apply the CHANGELOG transformation above. Use today's date.

# 4. Commit:
git add pyproject.toml src/ndl/__init__.py uv.lock \
        scripts/verify_distribution.py \
        tests/unit/scripts/test_verify_distribution.py \
        CHANGELOG.md
git commit -m "chore(release): NDL v0.2.0"

# 5. Local preflight + build + verifier + smoke against the release commit:
uv lock --check
uv run ruff check . && uv run ruff format --check .
uv run mypy src/ndl
uv run pytest --cov=ndl --cov-report=term --cov-report=xml
uv run pre-commit run --all-files
rm -rf dist && uv build --wheel --sdist --out-dir dist
uv run python scripts/verify_distribution.py \
    dist/ndl_storykit-0.2.0-py3-none-any.whl \
    dist/ndl_storykit-0.2.0.tar.gz
rm -rf /tmp/ndl-smoke && python -m venv /tmp/ndl-smoke
/tmp/ndl-smoke/bin/pip install --upgrade pip
/tmp/ndl-smoke/bin/pip install dist/ndl_storykit-0.2.0-py3-none-any.whl
/tmp/ndl-smoke/bin/python scripts/smoke_cli.py --ndl /tmp/ndl-smoke/bin/ndl

# 6. Push and open a release PR; wait for the green 15-cell matrix.
git push -u origin release/v0.2.0
gh pr create --title "chore(release): NDL v0.2.0" --body "..."

# 7. After merge, tag the merge commit on main:
git switch main && git pull
git tag -s v0.2.0 -m "NDL v0.2.0"   # or -a if no GPG configured

# 8. Push the tag:
git push origin v0.2.0

# 9. Create the GitHub Release pointing at the tag and using
#    docs/release-notes/v0.2.md as the body:
gh release create v0.2.0 --title "NDL v0.2.0" \
    --notes-file docs/release-notes/v0.2.md

# 10. Upload to PyPI:
uv publish dist/ndl_storykit-0.2.0-py3-none-any.whl \
           dist/ndl_storykit-0.2.0.tar.gz
# Verify the listing at https://pypi.org/project/ndl-storykit/0.2.0/

# 11. Follow-up commit bumping back to 0.3.0.dev0 in the same version-string
#     sites, plus a doc refresh round that flips all the "active development
#     version is 0.2.0.dev0" pointers to 0.3.0.dev0.
```
